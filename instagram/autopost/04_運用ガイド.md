# 04 運用ガイド

## 1. 毎日の確認（ログの見方）

- **Actions タブ**：毎朝の「Instagram auto post」の実行が並びます。
  - ✅ 緑：成功（または何もすることがなかった）
  - ❌ 赤：どれかの投稿が失敗。GitHub から通知メールが届きます
  - ⊘ 灰色（skipped）：スイッチ `IG_AUTOPOST_ENABLED` が `true` ではないので何もしていない
- **`instagram/autopost/post_log.txt`**：成功・失敗の記録（日本時間）。例：
  ```
  2026-10-13 09:41:02 JST [OK] feed #0 f01-blend media_id=1789…
  2026-10-13 09:41:15 JST [OK] story #0 s01-hours media_id=1790…
  2026-10-14 10:02:44 JST [FAIL] feed #1 f02-kyoto-moon-burger https://… ― コンテナ作成(/media) が失敗 (HTTP 400) 応答: {"error":…}
  ```
- **`instagram/autopost/state.json`**：種類ごとに「最後に投稿した番号（last_index）」「最後に投稿した日（last_posted_date）」。
  失敗した種類は更新されないので、次の日に同じものから再挑戦します。

**週に1回は Actions タブか post_log.txt を見て、❌ や [FAIL] が無いか確認してください。**

## 2. 失敗したとき

| ログに出る内容 | 原因と対処 |
|---|---|
| `IG_ACCESS_TOKEN または IG_USER_ID が設定されていません` | Secrets 未登録・名前の綴り違い。[02](02_Meta設定ガイド.md) のステップ6 |
| `HTTP 400` / `HTTP 401` で `Error validating access token`、`Session has expired`、`code":190` | **トークンの期限切れ・無効**。下の「3. トークンの更新」 |
| `公開URLが見つかりません (HTTP 404)` | 画像が公開されていない。ファイル名・場所を確認。アップロード直後なら数分待つ |
| `処理が ERROR になりました` | Instagram 側で画像・動画を受け付けなかった。JPEG か、サイズは正しいか |
| `秒待っても処理が終わりませんでした` | Instagram 側の混雑。翌日自動で再挑戦します |
| `HTTP 400` で `code":9` や `limit` | 投稿数の上限（24時間で100件）など。通常は起きません |
| push に失敗しました | Settings → Actions → General → Workflow permissions を **Read and write** に |

失敗しても、翌日の定時実行で自動的に同じ項目から再挑戦します。**慌てて手動実行しないでください。**

## 3. トークンの更新（約60日ごと）

1. [02_Meta設定ガイド.md](02_Meta設定ガイド.md) のステップ5 と同じ画面で **トークンを生成** → コピー
2. GitHub → **Settings → Secrets and variables → Actions** → `IG_ACCESS_TOKEN` の鉛筆（Update）→ 貼り付け → **Update secret**
3. 次の定時実行（または手動のドライラン → 翌日の定時実行）で確認

カレンダーに「50日後：Instagramトークン更新」と入れておくのがおすすめです。

## 4. 写真・キャプションを追加する／文字入れ画像を作り直す

Python などのインストールは不要です。すべて GitHub の画面で行えます。

1. **写真を追加**：`instagram/photos/` を開き **Add file → Upload files** で JPEG を追加
   - 黒板（Wi-Fi情報）・額装絵画（Sam Toft の作品）・はっきり写った人物・チラシや他社商品が大きく写ったものは使わない
   - 長辺 800px 以上（できれば 1500px 以上）。iPhone の写真はそのままでOK（HEIC の場合は JPEG で書き出し）
2. **投稿内容を追加**：`instagram/autopost/content.py` を開き、右上の **鉛筆（Edit）** をクリック
   - `FEED = [` の中の `dict( … ),` を1つコピーして下に貼り、`id`（半角英数とハイフン、他と重複しない）、`photo`、`headline`、`info`、`subline`、`caption` を書き換え
   - キャプションの形：日本語 → 空行 → 同じ内容の英語 → 空行 → 英語のハッシュタグ 10〜15個（日本語のハッシュタグは使わない）
   - 価格は税込で。確認できていない情報（価格・営業日など）は書かない
   - **Commit changes** で保存
3. **文字入れ画像を作る**：**Actions → Instagram generate overlays → Run workflow**
   - 数分で `instagram/generated/` に画像が作られ、自動で保存されます
   - 実行結果ページ下の **Artifacts → preview** をダウンロードすると、全画像の一覧（preview_feed.jpg / preview_stories.jpg）で仕上がりを確認できます
   - 文字が長すぎて入らないときは ❌ になり「文字が長すぎて収まりません」と出ます → `headline` を短く
   - 同じ実行で、キャプションのルール（価格・禁止語・ハッシュタグ数など）の自動チェックも行います
4. 投稿は翌日以降の定時実行に任せます（同じ日に作って投稿はしません）

**季節もの**：`months=[9, 10, 11]` のように書いた項目は、その月だけ投稿されます（今の秋の2件は9〜11月のみ）。冬・春の項目を追加するとよいです。

**並び順**：上から順に投稿します。途中に追加すると、次の一巡から反映されます。

## 5. 頻度を変える

`instagram/autopost/config.py` の `CADENCE` だけを編集します。

```python
CADENCE = {
    "feed":  {"enabled": True, "days": "daily"},                # 毎日
    "story": {"enabled": True, "days": ["mon", "wed", "fri"]},  # 月・水・金だけ、の例
    "reel":  {"enabled": True, "days": ["fri"]},                # 動画が登録されていれば金曜
}
```

- 種類ごとに止めたいときは `"enabled": False`
- 投稿時刻（毎朝9:00）は `.github/workflows/instagram-autopost.yml` の `cron: "0 0 * * *"`（UTC表記。日本時間−9時間）

## 6. リール（動画）を始めるとき

1. 動画を `instagram/videos/` に MP4 でアップロード（[../videos/README.md](../videos/README.md) の注意を必ず読む：**1本20MB以下目安、リポジトリが重くなり消しても履歴に残る**）
2. `content.py` の `REELS` の該当項目の `video=None` を `video="r01-espresso.mp4"` のように書き換え
3. `config.py` の `reel` の曜日に投稿されます（Instagram 側の処理を最大約5分待ちます）
- 音楽・スタンプは API では付けられません

## 7. 止める

- **すぐ止める**：Settings → Secrets and variables → Actions → Variables → `IG_AUTOPOST_ENABLED` を **`false`** に
- **完全に止める**：Actions → Instagram auto post → 右上「…」→ **Disable workflow**
- 種類ごとに止める：`config.py` の `enabled` を `False`

## 8. 二重投稿を防ぐルール

- 自動投稿は **GitHub Actions だけ**で動かす。PC のタスクスケジューラなどには登録しない
- Business Suite の予約投稿と同じ日に重ねない（自動投稿をオンにしている間は、予約投稿は使わない）
- 定時実行が遅れても **定刻＋4時間は待つ**。手動実行で `force` をオンにしない
- 同じ日の同じ種類は自動でスキップされます

## 9. 長く使うための注意

- **API のバージョン**：`config.py` の `API_VERSION = "v21.0"` は Meta の一覧で **2027年1月21日に提供終了予定**。それまでに `"v25.0"` など新しいものに変更し、ドライラン → 翌日の結果を確認してください。
- **GitHub の定時実行は、リポジトリに60日間更新がないと自動で止まる**ことがあります（通常は毎日の自動保存で更新されるので問題ありません。スイッチを `false` にして長く置いた場合は、Actions タブで再度有効化）。
- **トークン**の期限（約60日）。

## 10. 価格・営業情報が変わったときに直す項目

`content.py` の中で、次の項目に **価格** や **「定休日なし」** が入っています。変更があったら、該当項目の文字入れ（headline / info）とキャプションの両方を直し、「Instagram generate overlays」を実行してください。

**価格が入っている項目**（価格を変えたら必ず更新。`tests/test_content.py` の `ALLOWED_PRICES` も新しい価格に）

| 項目 | 内容 |
|---|---|
| f01-blend / s09-blend | 馬町ブレンド 一杯 ¥580 |
| f02-kyoto-moon-burger / s03-kyoto-moon-burger | 京都ムーンバーガー ¥1,000 |
| f07-omelette-sandwich | オムレツサンドイッチ ¥880（珈琲豆100gと同じ金額なので、必ず商品名と並べる） |
| f11-umamachi-burger | 馬町バーガー ¥1,300 |
| f09-beans / s02-beans | 珈琲豆 100g ¥880 ／ 200g ¥1,560 |
| f10-espresso / s05-espresso | エスプレッソ ¥400 |
| f14-cafe-latte | カフェラテ ¥630 |
| r01-espresso / r02-roasting（リール、未使用） | ¥400 ／ 豆の価格 |

**「定休日なし」が入っている項目**（**12月に年末年始の営業が決まったら**、その期間は差し替えるか一時停止）

| 項目 | 内容 |
|---|---|
| f05-visit | 文字入れ・キャプション |
| f12-hours / s01-hours | 文字入れ・キャプション（s01 は文字入れのみ） |
| r03-shop（リール、未使用） | キャプション |

一時停止は、項目に `enabled=False,` を1行足すだけです（再開するときはその行を消す）。
年末年始のお知らせはこの自動投稿ではなく、アプリから手動で投稿するのがおすすめです。
